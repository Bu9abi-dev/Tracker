Architecture Council Report

Question: Is the portfolio dashboard plan sound (financial maths, security, data layer, hard rules), and what should change before coding?

Verdict: The plan is sound once a few things are fixed. Fix the TWR first period, how the Personal view handles stale dates, where the token travels, and how the P2 rule is enforced, then build. Start with a hand-calculated golden TWR fixture.

Recommendation (adopted)

  1. TWR: the first snapshot is the base and has no return. Label the method as weekly Modified Dietz, flag large flows, and show when the chain is unreliable.
  2. Personal: value it only on dates where P1 and P3 both have a fresh snapshot (within a tolerance window), and show when data is stale.
  3. P2 barrier: make the separation type-level, add a test that Personal output never changes when P2 data does, and keep P2 out of the donut.
  4. Transfers: add a transfer marker for the P5→P1 merge. Raise a prominent flag when Invested changes and the row has no note.
  5. Auth: use a long random password and a logout. Make SESSION_SECRET rotatable, re-check the session in the data layer and server actions, and send no-store.
  6. Apps Script: send the token in the POST body, return ISO dates, and sanitise anything written to the Sheet.
  7. Resilience: show "last updated", and fall back to the last good data if a fetch fails.
  8. Add form: include a deposit helper that computes cumulative Invested, and make submission idempotent.

Where the council agrees

  • r0 = V0/I0 − 1 invents a gain when tracking starts mid-life.
  • Forward-filling stale values into the Personal series corrupts its TWR and drawdown.
  • A token in the query string ends up in Google's logs.
  • A delay on failed logins does nothing on serverless.
  • The P2 rule needs structural enforcement, not just a config flag.

Where it clashes

  • Personal fix: weighted chaining or common dates. The chairman chose common dates.
  • Security depth: KV rate limiting is over-engineering for one user.
  • Flow ledger tab: cleaner, but it changes the data model, so it's left as an option for later.
Blind spots from peer review
  • A mistyped cumulative Invested creates a phantom flow. The fix is a deposit helper in the Add form.
  • The installed iPhone app doesn't share Safari's cookies, so you log in once inside it.
  • Apps Script cold starts and quotas mean the app needs a fallback to the last good data.
  • The AED toggle must apply to chart axes, not just to the numbers.
  • Sample CSVs must be synthetic.
